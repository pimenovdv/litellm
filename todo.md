# План очистки и подготовки проекта LiteLLM к внедрению (Offline OpenAI Gateway)

## 1. Удаление внешних интеграций (Система без доступа в интернет)
- [x] Очистить директорию `litellm/llms/` от всех провайдеров, оставив только поддержку `openai/` и необходимые базовые классы. Удалить Anthropic, Gemini, AWS Bedrock, Azure, VertexAI и прочие.
- [x] Очистить директорию `litellm/integrations/`. Удалить все интеграции со сторонними SaaS и облачными сервисами: Datadog, Sentry, Langfuse, Helicone, Slack, AWS S3, Google Cloud Storage и т.д.
- [x] Удалить дополнительный неиспользуемый функционал: **RAG** (поиск и векторные базы), **Guardrails** (Lakera, LlamaGuard, защита от промпт-инъекций), менеджеры секретов (AWS KMS, Vault и т.д.).
- [x] Отключить скачивание актуальных цен на модели из сети (`model_prices_and_context_window.json`), заменить на локальный/статический конфиг и убрать механизмы его автообновления.
- [x] Удалить все вызовы телеметрии, проверки обновлений (например, Github API) и отправки аналитики.

## 2. Сохранение и адаптация целевого функционала
- [x] **Провайдер OpenAI**: Обеспечить полноценную работу с кастомными эндпоинтами (`api_base`) для интеграции с вашими внутренними сервисами.
- [x] **Маршрутизация (Routing)**: Обязательно сохранить поддержку Fallbacks и Load Balancing. Логика должна быть перестроена так, что "провайдером" выступает внутренний сервис (основной или fallback-узлы с форматом OpenAI API).
- [x] **Авторизация**: Сохранить и адаптировать генерацию и проверку API-ключей, управление пользователями и командами (модуль `proxy_auth`, RBAC).
- [x] **Учет и лимиты**: Оставить модули бюджетов (`budget_manager`), подсчет стоимости (`cost_calculator`), ограничение RPS/RPM/TPM (Rate Limiting). Убедиться, что они работают **только** с локальным Redis/PostgreSQL.
- [x] **Кэширование**: Оставить функционал "Exact caching" (точное совпадение промптов) через локальный Redis.
- [x] **Мониторинг**: Оставить локальные метрики (Prometheus `/metrics`) и health checks.
- [x] **База данных**: Убедиться, что PostgreSQL (через Prisma) и Redis используются для всех нужд (ключи, бюджеты, рейтрейт) в полностью закрытом локальном контуре.
- [x] **Non-text API**: Оставить базовую трансляцию запросов для Audio, Vision, Image поколений в формате OpenAI (для передачи на соответствующие локальные сервисы).

## 3. Разделение Backend и Frontend
- [x] Выделить Frontend-часть (`ui/litellm-dashboard` на Next.js) в полностью независимую часть системы, логически отвязанную от кодовой базы python-бэкенда.
- [x] Оставить весь функционал UI (управление ключами, пользователями, логами аналитики, маршрутизацией, песочница), но адаптировать его: раздел моделей/провайдеров должен настраивать внутренние адреса ваших сервисов, а не внешних SaaS.
- [x] Убедиться, что Frontend общается с Backend **только** по REST API. Настроить CORS и убрать любые жесткие связки.
- [x] Создать минималистичные, независимые `Dockerfile` для Backend и Frontend. Удалить старые сложные конфигурации деплоя (helm, terraform, render, railway).
- [x] Настроить новый `docker-compose.yml` для запуска всей связки из 4х контейнеров: Backend, Frontend, Redis, PostgreSQL.
