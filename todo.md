# План рефакторинга проекта

## 1. Разделение на Backend и frontend
- [ ] Создать корневую директорию `Backend` и перенести туда весь Python-код бэкенда (`litellm`, `gateway`, `enterprise`, `backend`, конфигурации).
- [ ] Создать корневую директорию `frontend` и перенести туда весь код пользовательского интерфейса (содержимое папки `ui`).
- [ ] Убедиться в полном разделении кодовой базы: отсутствие общих импортов, взаимодействие между `Backend` и `frontend` исключительно по REST API.
- [ ] Настроить и обновить `Dockerfile` для `Backend` и `frontend`, а также общий `docker-compose.yml` с учетом новой структуры папок.

## 2. Очистка репозитория от мусора
- [ ] Удалить все неиспользуемые интеграции из `Backend/litellm/integrations/` (Langfuse, Datadog, Sentry, Slack и др.).
- [ ] Удалить поддержку всех сторонних LLM-провайдеров из `Backend/litellm/llms/`, оставив исключительно `openai`.
- [ ] Вырезать лишний функционал из ядра системы (RAG, Guardrails, сторонние менеджеры секретов, телеметрию).
- [ ] Очистить корневую директорию от неактуальных артефактов (например, `.circleci`, `.devcontainer`, `.semgrep`, `litellm-proxy-extras`, `packaging` и др.).
- [ ] Очистить списки зависимостей (`pyproject.toml`, `requirements.txt`, `uv.lock`, `package.json` во фронтенде) от неиспользуемых библиотек.

## 3. Документирование кода
- [ ] Добавить и актуализировать docstrings для всех модулей, классов и функций бэкенда (`Backend/`).
- [ ] Добавить JSDoc-документацию и комментарии к компонентам, хукам и утилитам фронтенда (`frontend/`).
- [ ] Обновить корневой `README.md`: описать новую архитектуру, инструкции по развертыванию, запуску локально и добавлению нового кода.

## 4. Настройка GitHub Actions и тестов
- [ ] Реструктурировать тесты, удалив все интеграционные и e2e-тесты (оставить только `unit`). Переместить тесты в соответствующие папки для бэкенда и фронтенда.
- [ ] Настроить локальный сбор coverage (`pytest-cov` для бэкенда и `jest` для фронтенда).
- [ ] Очистить каталог `.github/workflows/` от устаревших actions и создать новые workflows для проверки PR.
- [ ] Настроить CI пайплайн: тесты должны покрывать **не менее 90% кода** (иначе пайплайн падает).
- [ ] Оптимизировать набор тестов так, чтобы время их выполнения гарантированно составляло **не более 45 минут**.
- [ ] Выполнить настройку производительности GitHub Actions (кэширование, параллельный запуск, оптимизация `uv` и `npm ci`) в последнюю очередь, когда базовое время прохождения будет стабильно ниже 45 минут.
